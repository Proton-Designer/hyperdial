Hyper Dialer Shifts Tab: Build Spec
Oct 6, 2026 · @Kareem
Overview
Add a Shifts tab to Hyper Dialer where interns pick any times they want each week in 30-minute steps (8 hour minimum, no cap) with the highest-leverage windows highlighted, see who else is working at each time, request changes with a written reason, and get scored per shift from their own dialer data. Henry approves requests and sees coverage and per-shift KPIs in a Team Shifts tab. Everything is pushed to GHL (shifts, submissions, requests, decisions, and KPIs) so all management automation runs on GHL workflows.
Source of truth: Supabase. The app writes shifts first, then syncs to GHL. GHL never decides anything; edits made directly in GHL get overwritten.

RLS
	•	Enable RLS on every new table.
	•	profiles, week_commitments, shifts, shift_change_requests, shift_kpis: SELECT where user_id = auth.uid() or is_manager().
	•	power_windows, open_hours, shift_settings: SELECT for any authenticated user.
	•	No INSERT/UPDATE/DELETE policies on any of them. All writes go through edge functions with the service role so the rules can't be skipped from the browser.
	•	dialer_session_events, ghl_outbox: no policies at all (service role only).
submit_week(p_user uuid, p_week_start date, p_blocks jsonb) (plpgsql, security definer, called only by shifts-submit-week). p_blocks is the intern's full pick for the week, e.g. [{"date":"2026-10-13","start":"07:00","end":"10:00","activity":"dialing"}, {"date":"2026-10-14","start":"12:30","end":"13:00","activity":"dialing"}]. In one transaction:
	•	Compute the deadline: ((p_week_start - 1) + lock_time) at time zone timezone. If now() is past it, raise deadline_passed.
	•	Validate each block: date inside the week, start and end on :00 or :30, end > start, both inside that weekday's open_hours row (no row means the day is closed), valid activity. Raise bad_block with the index otherwise.
	•	Sort by date and start. Merge blocks that touch or overlap and share an activity. Raise overlap if two overlapping blocks have different activities.
	•	Convert each to starts_at = (date + start) at time zone timezone, same for ends_at. This is what keeps DST correct.
	•	Sum hours. Raise under_minimum if below coalesce(min_hours_override, min_weekly_hours). No upper limit, no headcount check.
	•	Set each shift's power_minutes: for every active power window whose iso_weekdays includes that date, add greatest(0, least(end, window_end) - greatest(start, window_start)) in minutes.
	•	Diff against the intern's existing source = 'pick' shifts for that week, matching on exact starts_at, ends_at, activity. Mark removed ones cancelled and queue appointment_cancel. Insert new ones and queue appointment_upsert. Leave exact matches alone so their GHL ids survive.
	•	Upsert week_commitments with submitted_at = now(), scheduled_hours, and power_hours.
	•	Queue the GHL updates for the Week submitted event (see the event map in the GHL section).
Return the error codes as-is so the UI can show a specific message, like "You picked 6 hours, the minimum is 8."

Dialer tie-in and per-shift KPIs
The dialer already logs every call in call_logs and every session in dialer_sessions, but dialer-session-pause only flips status to paused and keeps no timestamp. Without pause and resume times there's no way to know how long someone actually dialed, so this part is required.
Session event logging
	•	dialer-session-start: after the session row is created, insert ('start', now()) into dialer_session_events.
	•	dialer-session-pause: insert pause.
	•	Wherever a paused session resumes (start or active function, whichever handles it now): insert resume.
	•	dialer-session-stop and any code path that sets status to completed (the engine sets it when the list runs out): insert stop.
	•	Use the server clock for at, never a time from the browser.
Active dialing time
Build intervals from the events: each start or resume opens one, the next pause or stop closes it. If an interval never closes (browser closed, crash), close it at the intern's last call ended_at in that session plus open_session_tail_minutes (5). Clip every interval to the shift window and add them up.
KPI definitions (calls counted when call_logs.started_at is inside [starts_at, ends_at) for that intern)
KPI
Formula
scheduled_minutes
ends_at - starts_at
active_dial_minutes
Sum of clipped active intervals (above)
power_active_minutes
Same, clipped to the parts of the shift inside power windows
adherence_pct
active_dial_minutes / scheduled_minutes x 100, rounded
first_dial_at
Earliest started_at in the window
last_call_end_at
Latest ended_at in the window
late_start_minutes
max(0, first_dial_at - starts_at), or the full shift if no dials
early_end_minutes
max(0, ends_at - last_call_end_at)
longest_idle_minutes
Largest gap between consecutive call starts, including shift start to first dial and last call end to shift end
dials
Count of rows
connects
amd_result in ('human','not_sure')
conversations
Connects with duration_seconds >= conversation_min_seconds (60)
voicemails
amd_result = 'machine'
no_answers
status = 'no_answer'
talk_minutes
Sum of duration_seconds on connects / 60
dials_per_active_hour
dials / (active_dial_minutes / 60), null if 0 active
connect_rate_pct
connects / dials x 100
dispositions
{ "Yes: profile build": 2, "Not a fit": 4, ... } grouped from call_logs.disposition
Note: status ends as completed for most answered calls, so count connects from amd_result, not status. If dispositions only live in GHL after your sync work, write them back to call_logs.disposition when the intern saves the disposition so this job can read them.
Flags (stored in shift_kpis.flags)
	•	no_show: zero dials in the window
	•	late_start: late_start_minutes > grace_minutes (10)
	•	left_early: early_end_minutes > grace_minutes (10)
	•	long_idle: longest_idle_minutes > idle_flag_minutes (20)

Every 15 min

GHL integration
Everything the app knows goes to the intern's GHL contact so Kareem and Henry can run all management automation as GHL workflows. Shifts become appointments, current state lives in custom fields, every event adds a tag (which triggers workflows), and the full history is kept as notes. Data flows one way, app to GHL. All calls run server-side from ghl-sync; the token never touches the browser.

ghl-sync processing rules
	•	Select up to 50 rows where status = 'pending' and next_attempt_at <= now(), ordered by id, using for update skip locked so two runs never send the same row.
	•	Process rows for the same contact in id order. Queue fields before the tag for every event so a workflow triggered by the tag always reads fresh field values.
	•	Event tags: always send DELETE then POST for the tag. GHL's Tag Added trigger only fires when the tag is new, so this makes the same event fire every time it happens.
	•	Skip and mark error ("intern has no GHL contact id") if the profile has no ghl_contact_id.
	•	Before sending an appointment_upsert, re-read the shift so a stale payload never wins. If the shift is now cancelled, send a cancel instead.
	•	Success: status = 'done'; for appointments set shifts.ghl_sync_status = 'synced'.
	•	Retryable failure: attempts + 1, next_attempt_at = now() + 2^attempts minutes, and hold later rows for that contact so order is kept. After 6 attempts, status = 'error' and copy the message to shifts.ghl_sync_error, which shows in Henry's sync health panel.
	•	Space requests by about 100 ms and stop the batch on a 429.
GHL workflows (Kareem builds)
	•	Shift reminder. Trigger: Customer Booked Appointment, calendar = Intern Shifts. Wait until 30 min before start, then SMS the intern and post to the Google Chat call-floor space with a Webhook action to its incoming webhook URL.
	•	Not submitted. Tag added shift-evt-not-submitted: SMS the intern, internal notification to Henry.
	•	Under minimum. Tag added shift-evt-under-minimum: notify Henry with {{contact.shift_hours_next_week}}.
	•	New request. Tag added shift-evt-request-created: notify Henry with the type and {{contact.shift_last_request_reason}}. Separate workflow on shift-evt-request-late for an urgent SMS.
	•	Request decided. Tags shift-evt-request-approved / -denied: SMS the intern the decision and {{contact.shift_last_request_note}}.
	•	Missed shift. Tag added shift-evt-missed: notify Henry; if shifts_missed_total is 2 or more, create a task for Henry to hold an attendance 1:1.
	•	Flagged shift. Tag added shift-evt-flagged: notify Henry with {{contact.last_shift_flags}}.
	•	Power week. Tag added shift-evt-power-week: post {{contact.week_power_summary}} to the Google Chat wins space, SMS the intern a congrats, and notify Henry so he can mention it in their 1:1.
	•	Week closed. Tag added shift-evt-week-closed: feeds the Monday KPI report from the week_* fields, including the Power week list.
These are starting points. Since every event is a tag and every number is a field, any other management workflow can be built in GHL without touching the app.
Optional: full event payloads. If a workflow needs more than the fields hold, add an outbox kind event_webhook that POSTs { event, contactId, occurredAt, data } to a GHL Inbound Webhook trigger URL stored as GHL_EVENTS_WEBHOOK_URL. Inbound Webhook is a premium trigger in GHL; tags work on any plan.
Optional, phase 2: GHL to app. If Henry ends up cancelling shifts in GHL, add a workflow (Appointment Status changed on Intern Shifts) with a Webhook action to a new ghl-appointment-webhook function that checks a x-webhook-secret header against GHL_WEBHOOK_SECRET and marks the matching shift cancelled. Until then, the rule is: change shifts in Hyper Dialer only.
